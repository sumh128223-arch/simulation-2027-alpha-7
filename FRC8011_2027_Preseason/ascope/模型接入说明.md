# 两个新 GLB 的实时可视化

1. 停止旧仿真，在 WPILib VS Code 中重新运行 Simulate Robot Code。
2. 在 AdvantageScope 的 Use Custom Assets Folder 菜单选择本项目的 ascope/assets 文件夹（不要选择 ascope 或 Robot_8011 子文件夹）。
3. 用 File → Import Layout 导入 ascope/layout-8011-live.json。
4. 用 File → Connect to Simulator 连接，打开 3D Field。
5. Robot 和 Robot Component 的模型均应为 8011 GLB 2027。旧用户资源中已有同名 8011 FAKER，新名字用于避免读取旧模型。
6. 将手柄分配到端口 0，启用 Teleop。按住 LT 展开并吸球，松开 LT 后仿真会收起。实际吸球还需要把展开的 intake 驶向球；代码吸球区域在机器人 -X 方向。

layout-8011-live.json 已隐藏两个 Duck Bot Ghost 及青色视觉连线，方便检查模型。重新导入布局即可生效，无需为这项布局修改重启仿真。

assets/Robot_8011/model_0.glb 来源于 mainrobot.glb；model_1.glb 来源于 intake.glb。model.glb 是空基础模型。config.json 只有两个组件，与代码发布的组件数组一致。分发副本只保留最终配置，不包含根目录重复 GLB 或旧模型目录。

机器人位置数据：/AdvantageKit/RealOutputs/Odometry/EstimatedPose。
组件数据：/AdvantageKit/RealOutputs/Visualization/Components。
如果数据行失效，请从左侧实时数据树拖入这两项，分别选择 Robot 和 Robot Component。

新模型自身为 Z 轴向上，主体现在仅绕 Z 轴旋转 -90 度，不再使用旧模型的 X 轴 90 度旋转。intake 文件是水平展开姿态，因此 0 度对应模型导出姿态，99 度对应收起。先在 config.json 中减去转轴坐标，再由 RobotContainer.java 加回安装坐标；在 0 度时，两个平移相消，恢复两个新 GLB 原有的装配关系。

当前 intake 转轴初值为模型坐标 [0, -0.30235, 0.2075] 米，根据几何侧视检查得到，尚非 CAD 标注的实测铰链坐标。需用收起与展开画面确认；如果仍绕错轴运动，要同步修改代码安装坐标和 config 中相反的 zeroedPosition。

Line Graph 现显示 LT（左轴）和 intake 角度（右轴）。LT 按下应从 0 接近 1，角度应从 99 到 0；松开后回到 99。若 LT 完全不变，检查 GUI 手柄分配的端口 0。若 LT 变化但角度不变，检查 Enabled、Teleop 状态及仿真是否重启了新代码。诊断数据位于 /AdvantageKit/RealOutputs/Simulation。

已修复仿真 DEPLOY 时正负电流令模型在端点间反复跳变的问题，并在 Disabled 时停止 intake 输出。代码修改后须完全停止旧仿真再重新运行；只重新导入 layout 不会加载新 Java 代码。
